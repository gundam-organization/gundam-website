A practical learning path

  1. Install a tagged release.
    Verify the GUNDAM applications are available in your shell.
  2. Clone the input tutorials.
    Begin with a maintained example instead of an analysis-specific configuration.
  3. Read the top-level configuration.
    Follow each included YAML file to understand the job structure.
  4. Run and inspect.
    Confirm the output, minimizer status, and post-fit diagnostics before modifying the model.

Configuration

Compose the analysis from YAML

GUNDAM reads YAML or JSON configuration. A string ending in .yaml can include another file relative to the current working directory, allowing large configurations to be separated by purpose.

minGundamVersion: 2.0.0
fitterEngineConfig:
  minimizerConfig: "./minimizerConfig.yaml"
  likelihoodInterfaceConfig: "./likelihoodConfig.yaml"

Keep related blocks—such as the minimizer, likelihood, parameter sets, samples, and plot settings—in focused files with descriptive names.

Run a First Fit

Establish a known-good baseline

Use the executable and command supplied by the selected tutorial. Before introducing analysis-specific changes, save the complete terminal output and confirm:

  • all configuration includes resolve to the expected files;
  • input samples and parameter sets initialize successfully;
  • the minimizer reports a valid status;
  • the output ROOT file is created at the configured location; and
  • the post-fit point corresponds to a lower −2 log(L) than the starting point.

Fit Diagnostics

Treat convergence as a physics diagnostic

A non-converging fit is not automatically a software failure. Model parameterization, uncertainty correlations, discontinuities, weakly constrained directions, and input choices can produce a difficult likelihood surface.

Inspect pre-fit and post-fit predictions, parameter pulls and constraints, covariance information, step-by-step minimizer output, and one- or two-dimensional likelihood scans where appropriate.
